# Test Results

## Transaction Processing API

This document contains the automated test results and manual API testing performed for the Transaction Processing API.

## Detailed Test Results

### TC01 — Transaction Created Successfully

**Objective:**  
Verify that a valid transaction can be created successfully.

**Test Scenario:**

* Send a valid transaction request.
* Provide a valid Transaction ID and required transaction details.

**Expected Result:**  
The transaction should be created successfully and the API should return `HTTP 201 Created`.

**Actual Result:**  
The transaction was created successfully.

**Status:** PASS

---

### TC02 — Transaction Rejected Because of Validation Failure

**Objective:**  
Verify that invalid transaction data is rejected by the API.

**Test Scenario:**

* Send a transaction request with an invalid transaction amount.

**Expected Result:**  
The API should reject the request and return `HTTP 400 Bad Request`.

**Actual Result:**  
The invalid transaction was rejected and the validation error response was returned.

**Status:** PASS

---

### TC03 — Duplicate Transaction ID Rejected

**Objective:**  
Verify that duplicate Transaction IDs are not allowed.

**Test Scenario:**

1. Create a transaction with a valid Transaction ID.
2. Submit another transaction using the same Transaction ID.

**Expected Result:**  
The second transaction should be rejected because the Transaction ID already exists.

**Actual Result:**  
The duplicate Transaction ID was detected and the second transaction was rejected with `HTTP 409 Conflict`.

**Status:** PASS

---

### TC04 — Transaction Not Found

**Objective:**  
Verify that the API correctly handles a request for a transaction that does not exist.

**Test Scenario:**

* Request a Transaction ID that is not present in the system.

**Expected Result:**  
The API should return `HTTP 404 Not Found`.

**Actual Result:**  
The API returned `HTTP 404 Not Found` as expected.

**Status:** PASS

## Manual API Testing

All four required REST APIs were also manually tested using **Postman and PowerShell**.

The following scenarios were verified:

- Successful transaction creation → `201 Created`
- Invalid transaction amount → `400 Bad Request`
- Non-existent transaction → `404 Not Found`
- Duplicate Transaction ID → `409 Conflict`
- Successful transaction status update → `200 OK`
